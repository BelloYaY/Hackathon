# LucentID Core - 8-Slide Deck + 4-Person Script

## Slide 1: Title and One-Line Pitch
### Slide Content
- `LucentID Core: Live Zero Trust Identity Control Plane`
- Team name, members, hackathon track
- One-liner: `We built a real backend security engine with live detection, not a mocked auth demo.`

### Speaker Notes
- Open with the problem in one line: modern attacks bypass basic login checks.
- Clarify your differentiator immediately: runtime enforcement + observability + containment.

---

## Slide 2: Problem We Are Solving
### Slide Content
- Password-only authentication assumes trust after login.
- Static sessions are vulnerable to:
- token theft
- replay attacks
- session hijacking
- device impersonation
- Most hackathon demos simulate security logic in frontend only.
- Security teams need live controls: detect, decide, and contain in real time.

### Speaker Notes
- Emphasize that attackers usually abuse sessions and tokens after initial auth.
- Mention why this matters in fintech/enterprise: high blast radius and compliance pressure.

---

## Slide 3: Our Solution (LucentID Core)
### Slide Content
- Continuous Zero Trust evaluation on every protected request.
- Inputs used per request:
- identity assurance
- device posture
- session health
- behavior anomalies
- trust score + risk class
- policy rules
- Dynamic enforcement outputs:
- allow
- step-up
- deny
- contain (lock/revoke path)

### Speaker Notes
- Explain that this is not “login and forget”; trust is recalculated continuously.
- Show decision flow visually if possible (input signals -> policy engine -> action).

---

## Slide 4: Architecture and Real Integration
### Slide Content
- Backend: Node.js Express API with real persistence and security pipelines.
- Frontend: React TypeScript live console connected to existing backend routes.
- Core route groups:
- `/api/v1/auth`, `/session`, `/trust`, `/device`, `/token`
- `/api/v1/vault`, `/policy`, `/monitor`, `/audit`
- No fake endpoints, no frontend-only security simulation.
- User mode and admin mode are role-gated from backend roles.

### Speaker Notes
- State clearly: every interface action calls a real API route in LucentID Core.
- Mention tenant-bound headers and token/device context are enforced by middleware.

# 4-Person Script (Recommended 7-8 Minute Flow)

## Presenter Roles
- **Person 1**: Context + Problem + Solution
- **Person 2**: Architecture + Product Interfaces
- **Person 3**: Security Controls + Evidence
- **Person 4**: Live Demo + Close

## Slide-by-Slide Script

## Slide 1 (Person 1, ~40s)
`Hi everyone, we are [Team Name], and this is LucentID Core. Our project is a live Zero Trust identity control plane. The key point is simple: we are not showing a mocked authentication UI. We are showing real runtime security decisions and containment from a real backend engine.`

## Slide 2 (Person 1, ~55s)
`The problem is that most systems still trust too much after login. Even if credentials are correct, sessions and tokens can be stolen, replayed, or hijacked. In many demos, security logic is simulated in frontend logic, so you never see true enforcement. In real organizations, teams need live controls that detect and contain threats immediately.`

## Slide 3 (Person 1, ~55s)
`Our solution is continuous trust evaluation on every protected request. We combine identity assurance, device posture, session health, behavior signals, trust score, risk class, and policy. The output is dynamic: allow, step-up, deny, or contain by locking or revoking. So trust is continuously recalculated, not granted once at login.`

## Slide 4 (Person 2, ~55s)
`Architecturally, LucentID Core is a Node.js backend with real persistence and security pipelines. The frontend is React TypeScript and connects directly to real routes under /api/v1. We integrated auth, session, trust, device, token, monitor, audit, policy, and vault routes. No fake endpoints and no simulated backend security logic.`

## Slide 5 (Person 2, ~60s)
`We expose three interfaces on top of the same backend engine. First, a normal user demo app with live trust and risk posture. Second, an attack simulator that runs real attack paths and returns blocked or allowed outcomes with trust deltas. Third, a SOC monitor that shows overview metrics, risk events, behavior events, and audit integrity in near real time.`

## Slide 6 (Person 3, ~65s)
`Security controls include tenant isolation, adaptive lockout, MFA, step-up authentication, token rotation and revocation, replay protection, hardware-bound device attestation, and hijack/spoof detection with containment. We validated this with automated tests: 13 test files, 32 tests, all passing. That includes attack simulations and core control verification.`

## Slide 7 (Person 4, ~70s)
`For the live demo, we will do four quick steps. First, login as a normal user and show app-style dashboard data. Second, run a quick action that executes real backend logic and changes trust. Third, switch to admin and run attack simulations. Fourth, open SOC monitor and show the resulting alerts and events generated from those actions.`

## Slide 8 (Person 4, ~50s)
`What this demonstrates is practical: real-time security control with measurable impact, not static auth checks. We can support both user-facing flows and security operations from the same platform. Next, we would harden with KMS/HSM custody, SIEM export, and production HA controls. LucentID Core is a working control plane, not a mock login screen. Thank you.`
